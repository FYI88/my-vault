# SEC-001 — Renderer-exposed IPC can read, write, and overwrite arbitrary file paths

> *This was generated by AI during triage.*

## Agent Brief

**Category:** bug
**Summary:** Renderer-exposed IPC can read, write, and overwrite arbitrary file paths

**Current behavior:**
The preload bridge exposes file operations (`readFile`, `writeFile`, `writeFileAtomic`, `copyFile`, `exists`, `isDir`, `reveal`) that accept a path supplied by the renderer, and the main process acts on it with no validation or allowlist. Every path the app legitimately uses originates from main's own dialogs (folder picker, vault picker, save dialogs) or from the remembered vault path — the renderer never needs arbitrary paths. Today there is no script-injection sink in the renderer (zero user-controlled innerHTML, `script-src 'self'`), so the surface is unreachable — but if any future bug yields script execution, the blast radius is read/write/overwrite of every file the user can access, including replacing vault files or dropping executables.

**Desired behavior:**
The main process maintains a trusted-paths set populated only from its own dialog results (folder picker, vault picker, save-as dialogs) and the remembered vault path. Every file IPC handler validates its path against that set (or a descendant of a picked folder) before touching the filesystem and returns an error otherwise. The renderer's API shape stays the same — it never supplies a path main did not mint.

**Key interfaces:**
- The file IPC handlers in the main process: the shared validation gate every handler passes its path through before any filesystem call.
- The dialog handlers: they must register their returned paths into the trusted set.
- The renderer bridge: unchanged behaviorally, so no renderer changes are needed beyond what already exists.

**Acceptance criteria:**
- [ ] Calling any file IPC with a path that did not come from a dialog or the remembered vault path returns an error and touches nothing on disk.
- [ ] All existing flows still work: create vault, open vault file, save backup, export a copy, atomic saves of the vault file.
- [ ] Re-audit: the follow-up security-audit run marks this finding resolved in `findings.json`.

**Out of scope:**
- Adding new IPC surface, changing the dialog flow, or moving crypto between processes.

**Evidence:**

- CWE: CWE-749

- Suggested fix: trusted-paths set in main, populated only from dialog results; validate every file IPC path against it before any filesystem operation.
